# agentspaces-a2ui changelog

What changed in the A2UI records, the pen, and the open catalogs, newest first.

## Unreleased: 0.7.0

The cutover to A2UI 1.0, with no 0.9 reading kept (srad/agentspaces-geo.md, GEO-V-01 to V-03).

- **A heatmap mark, a table filter by a path, a row action that picks, and a task-state column** (srad/agentspaces-geo.md GEO-D-08 to D-11). All additive and optional; no application words.
  - **`Visualize mark: heatmap`** with `row` (the column down the side; `x` runs across, `y[0]` and `aggregate` keep their meaning, a count with no `y`), `xOrder` and `rowOrder` (fixed category lists, each drawn even when empty, 1 to 400 each), `facet` (small multiples, at most 8), `pick: {by}` (only the rows of the picked keys, every row while none is), `map` (the GeoMap whose pick set and view it uses outside a GeoLayout), `focus` (a column holding a map feature id, flown to on a click), `cellAction` (dispatched with `{row, x, y, value, facet}`) and `selected` (a data model path the click writes the cell's first row to; a second click writes null). Builders `Surfaces.heatmap`, `Surfaces.heatmapPick`, the constants `Surfaces.HOURS` (`"00"` to `"23"`), `Surfaces.WEEKDAYS` (`"Sun"` to `"Sat"`) and `Surfaces.HEATMAP_OPTIONS`; `Surfaces.visualize` refuses those options on any other mark and a heatmap without its `row`.
  - **`DataTable.rowFilter`** = `{path, match}` (`match` a column or a list of columns): only the rows whose columns equal the value at `path`; an object there is compared on the match columns, a key or a list of keys on the first; an empty value keeps every row. Builders `Surfaces.rowFilter`, `Surfaces.checkRowFilter` (shared with agentspaces-geo's layer filter).
  - **`DataTable.rowActions[].pick`** = `{from, map?, dispatch?}`: in place of a dispatch, sets the map's pick set to the first eight keys of the row's column; with `dispatch: true` it dispatches the action with `{row}` beside the pick, for an action that brings the keys' rows (the keys no table lists yet are picked too). Builders `Surfaces.tablePickAction` (and its overload with `dispatch`).
  - **`DataTable` column `format: state`**: an A2A task state as its word beside its icon in its colour. The `format` property is described; it stays a free word.
  - Goldens: `Visualize/heatmap`, `heatmap-empty`, `heatmap-loading`, `heatmap-error`; `DataTable/tasks`, `tasks-empty`, `tasks-loading`, `tasks-error`.

- **A table that picks, several row buttons, and a toolbar action that asks first** (srad/agentspaces-geo.md GEO-D-06, GEO-D-07). All additive and optional.
  - **`DataTable.select`** = `{key, map?, max? (1 to 8, default 8), label?, clearOn?, focus?}`: a checkbox per row that adds the row's `key` column to a map's pick set (agentspaces-geo's state rule, `picked`: browser memory only); `clearOn` names a column whose change empties the set; `focus` names a column holding a map feature's id, and the first column's words then fly the map to it. Builder `Surfaces.tableSelect`.
  - **`DataTable.rowActions`** = `[{action, label}]`: several row buttons beside `rowAction`, each dispatching `{row}`. Builder `Surfaces.tableAction`. **`DataTable.emptyText`**: the table's own words while it has no row.
  - **`Toolbar.actions[].confirm`** = `{title, text?, yes?, no?}`: a modal confirm before the action is dispatched; `text` is literal words or a data model path (as `Notice.text`). Builders `Surfaces.confirm` and `Surfaces.toolbarAction`; `Surfaces.toolbar` checks a confirm it is given.
  - `Surfaces.dataTable(id, columns, rows, options)` takes every other DataTable property as an option and refuses one the catalog does not declare. Goldens: `DataTable/select`, `DataTable/actions`, `DataTable/empty`, `Toolbar/confirm`, `Toolbar/confirm-bound`.

- **A2UI 1.0 final** (reviews/A2UI-1.0-FINAL-UPGRADE-2026-11-18.md). The cutover was built on the 1.0 release candidate in `@a2ui/web_core` 0.15.0. The final 1.0 (stable since 2026-11-05) moves a component's envelope keys into the `@` namespace (spec §2.9). Envelope versions, bindings and the basic catalog id do not change.
  - **The open catalogs.** Every component of `agentspaces-viz` and `agentspaces-widgets` declares `@catalogId`, `@accessibility` and `@metadata` in place of the bare names. `id` and `component` stay bare, as do the catalog's own `catalogId` and `metadata`. `widgets_catalog.json` is regenerated. `surfaces.json` and the CBOR vectors do not change.
  - **The builders.** `Surfaces.bindings` refuses a bare `catalogId`, `accessibility`, `metadata` or `checks` that the component does not declare, and names the `@` key. It refuses any other single-`@` key at a component's root. Below the root, a key matching `^@([^@]|$)` other than `@path` or `@call` is refused, since 1.0 reserves it; a literal key is written doubled (`@@type`). A builder option named for an envelope key is refused the same way. `Surfaces.ENVELOPE_KEYS` lists the four keys.
  - **The renderer followed on 2026-11-24.** `agentspaces-a2ui-react` moved to `@a2ui/react` and `@a2ui/web_core` 0.16.1, the first release with the 1.0 final, and generates from these catalogs again; its build check passes.

- **Follow-ups, thumbs, a lit path, a row button's words and a marking line** (issues/ISSUE-A2UIFollowUpsAndPathHighlight.md, AF-1 to AF-19). All additive: a page that sends a suggestions list, a graph with no `lit`, a table with no label or a layout with no banner draws as before.
  - **Chat `suggestions`** is a list of strings, as before, or a `DataBinding` to rows the agent writes (`oneOf` in the widgets catalog). A bound item is a string or `{text, label, line}`: `text` is the line a tap sends, `label` (at most 60 characters) the chip's words, and `line` the agent line the chip follows. A chip with a `line` draws only while that line is the newest line of the thread; a row with no `line` always draws, so starters are rows too. At most 8 chips draw, each cut at 120 characters and sent whole. `Surfaces.chat` takes the binding in its options and checks it as every binding is checked: v0.9.1's `{"path": ...}`, a binding with anything beside `@path`, and a list of rows are refused.
  - **Chat `feedback`** is described as two icon buttons, thumbs up "Helpful" and thumbs down "Not helpful", each with its pressed state. The action and its payload (`chat.feedback`, `{line, key, value}`) do not change.
  - **Graph and GraphView** say that node and edge rows may carry `lit: true`, and what each component does with them. `lit` is row data, so the builders take no new option.
  - **DataTable `rowActionLabel`** is the row button's words. `Surfaces.dataTable(id, columns, rows, rowAction, rowActionLabel)` writes it, and refuses a label with no action.
  - **The conversation layout's `banner`** (`Publish.BANNER`): one line of plain text, at most 120 characters (`Publish.BANNER_MAX`), that a host draws at the very top of the page and again at its foot. `Publish.conversation(chat, size, areas, kicker, banner)` writes it inside `options.layout`, trimmed, and leaves it out when blank; a line break or a longer line is refused. No record gains a field.
  - **Goldens.** `surfaces.json` gains a Chat with bound follow-ups (`chat-followups`), a Graph and a GraphView with a lit path (`graph-lit`, `graphview-lit`) and a DataTable with a label (`datatable-labelled`); a frame component's four states still come first, and a variant follows them. The vector `publish_conversation_banner_cbor.hex` pins a Publish whose conversation layout carries a banner.

- **Visualize and GraphView goldens in four states** (GEO-Q-31): full, empty (a table with no row), loading (the table not arrived yet) and error (a value at its path that is no table), as the frame components have. The full ones keep their surface ids.
- **The wire.** Every envelope says `"version": "1.0"`, the basic catalog is `https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json`, and a data binding is `{"@path": ...}`. The pen refuses a binding in the old `{"path": ...}` form, naming the property.
- **Component ids.** An id is a UAX #31 identifier, as 1.0 requires. The pen refuses one that is not, such as `bar-menu`, and suggests the camelCase form.
- **The GeoLayout** (srad/agentspaces-geo.md §3.3). `Publish.geo(map, windows)` and `Publish.geoWindow(page, label, icon, open, dock)` set `options.layout` to `{ kind: geo, map, windows }`: the map's page full screen under a top bar, and each window a page over it, opened from the bar. Windows dock `left`, `right`, `bottom` or `free` (`Publish.DOCKS`).
- **Visualize and GraphView** (srad/agentspaces-geo.md phase 5) join `agentspaces-viz`:
  - **`Surfaces.visualize(id, rows, mark, x, y, options)`** charts a bound table by a spec: bar, column, line, area, scatter or table, with `color`, `aggregate` and `sort`.
  - **`Surfaces.graphView(id, nodes, edges, layout, options)`** lays out a nodes table and an edges table, or GeoFeatures and their links, by force, as a tree, or in layers.
  - Both builders check their options against the catalog, and both have golden surfaces. `Chart` and `Graph` are unchanged.
- **`Surfaces.componentId(id)`** is public and returns the id, so another catalog's builders (agentspaces-a2ui-geo's) check an id the same way.
- **A button's label.** `Surfaces.button` names its label child `<id>Text` (it was `<id>-text`), so the label you write with `Surfaces.text` takes that id.
- **Headings.** 1.0's Text has only the `caption` and `body` variants, so `text(..., "h2")` writes a markdown heading instead.
- **The open catalogs.** `agentspaces-viz` and `agentspaces-widgets` are 1.0 catalog documents: `protocolVersion` "1.0", a `component` const for each component, and the rules under `metadata.extensions`.
- **Closed components and `$defs`** (GEO-V-04). Every component schema of both catalogs says `additionalProperties: false`, so a property the catalog does not declare is refused, by the feed and by any 1.0 validator. Each component also declares 1.0's envelope properties (`id`, `catalogId`, `accessibility`, `metadata`). Each catalog has `$defs`: `anyComponent` (every component by reference), `anyFunction` (no functions of its own), and the shared types (`ComponentId`, `DataBinding`, `TextOrBinding`, `NamedAction`, `HeaderAction`, `Accept`). Both documents meet web_core 0.15.0's `catalog_definition.json`. A builder's option can no longer be `id` or `component`.
- **Agent functions** (GEO-V-07). A component's action may call one of the drawing agent's functions, A2UI 1.0's `callAgentFunction`:
  - **`Surfaces.functionCall(function, args)`** writes 1.0's `{"functionCall": {"@call": ..., "args": {...}}}`, and **`Surfaces.functionButton`** is a button that makes it. The arguments go through the binding check. The name is an identifier of at most 64 characters, and none of `Surfaces.RENDERER_FUNCTIONS`, the basic catalog's own.
  - **The call reaches the agent as a `SurfaceAction`** whose action carries `functionCallId`, with the function as its `name` and the arguments as its `context`. `callsFunction()`, `functionCallId()`, `function()` and `args()` read it. They have no get or is prefix, so a mapper adds nothing to the record's bytes. `pen.actions()` now tells two calls apart by their ids.
  - **`FunctionResponse`** is a new open record in `records` (`https://badmonkey.ai/agentspaces/a2ui/v1/FunctionResponse`, space `views`, leased a minute). It carries the call's app, surface, session and id, and a value or a `Failure(code, message)`. The value is JSON of at most 32,768 characters as JSON writes it, escapes included, and 16 levels, with no NaN or infinite number. `pen.answer(call, value)` and `pen.fail(call, code, message)` write it. `A2uiRecords.RECORDS` lists five records. There is no golden vector for it.
- **No old binding anywhere** (GEO-V-05). Every builder walks every property and option value, however deep, and refuses v0.9.1's `{"path": ...}` binding and `{"call": ...}` function call, naming where it sits (`Map.follow`, `Chart.series[0].color`, `Menu.items[].checked`). Before, only TitleBar's title, a menu item's check and FilePreview's file were checked. A property the catalog declares as `path` (a Map layer's, a Chart series') is not a binding and passes. An action context's keys are names, so an entry called `path` with a literal passes. `Surfaces.binding(catalog, where, value, schema)` and `Surfaces.bindings(catalog, component)` are public, so another catalog's builders walk their components the same way.

## Unreleased: 0.6.0

The first release of agentspaces-a2ui on Maven Central, from its own repository. It builds on the AgentSpaces 0.6.0 core.

- **The records.** `Surface` carries one A2UI v0.9.1 envelope of a surface with its app, surface id, catalog, and sequence number. `SurfaceAction` carries a renderer's action on a surface with the session it came through. `Publish` asks the group's app host to serve an app's surfaces for end users, behind the host's identity provider (`signOn: idp`, the default) or open to anyone (`none`). `PublishStatic` asks it to serve a static app, a `StaticBundle` of files on the group's content swarm named by its content root. Every record is version 1.
- **The pen.** `Surfaces` writes a surface's envelopes in order and hands back each action once. It has builders for the basic catalog's common components and for every `agentspaces-viz` component, `draw` for a surface authored elsewhere, and `publish`. An update of one path of the data model is leased for a minute by default, so a stream of updates does not fill a space every member replicates.
- **Static apps.** A path stays inside the app's directory: no `..`, no hidden file, nothing that needs escaping in a URL. A media type follows RFC 6838's lower-case form. `StaticBundle.decode` reads under the strict wire read, and `open(publish)` returns the files only when the bundle holds exactly the ones the publish names.
- **The open catalogs.** `agentspaces-viz` holds Chart, DataTable, Map, Graph, Timeline, Report, Notification, Form, and Stat, and the panels Window, Conversation, Notice, Toolbar, KeyValue, and Prose. Beside it is the look-and-feel JSON Schema, which carries tokens only. `agentspaces-widgets` holds ChatInput, FileShare, ApprovalCard, and TimelineStrip, with entry types under `https://badmonkey.ai/agentspaces/a2ui/v1/`. All three documents ship in the jar.
- **Pinned bytes.** Seven golden CBOR vectors pin the records, and golden JSON pins the widgets catalog and one surface per component. A record refuses a null app or surface id where it is built, and `RecordContractsTest` holds every record in the package to that policy.
- **The frame of a page (spiral 6 phase 4, 2026-11-10).** `agentspaces-viz` gains `TitleBar` (the app's name and icon, a subtitle, a status read from `WorkingOn` rows, actions, and a `Menu` as its overflow), `Menu` (a menu button, an overflow, or a context menu, with groups, checked and disabled items, shortcuts, and one level of submenu), and `Split` (two or three panes with sizes, minimums, collapse, and a stacking width). `Window` gains `actions` and `Toolbar` gains `menu`. `Surfaces` has a builder for each, and `Publish` names the options `navigation` (tabs or a rail) and `layout` (whole surfaces in the panes of a split) with helpers. Each new component has golden surfaces in four states: full, empty, loading, and error.
- **The open records (spiral 6 phase 4, 2026-11-10).** The package `ai.badmonkey.agentspaces.a2ui.records` holds `ChatMessage` and `SharedFile` (versions 1 and 2), `WorkingOn` and `ChatProgress` under `https://badmonkey.ai/agentspaces/a2ui/v1/`. A version 2 field is omitted while null, so a version 1 value keeps the version 1 bytes. `A2uiRecords` gives the member hint `a2ui.records=2` and the writer's rule. Each constructor enforces its bounds, and six golden vectors pin each version's CBOR beside its JSON (SPEC v0.1.33 §6.1a.7). The open React renderer of these catalogs is the separate package `@agentspaces/a2ui-react`.
- **The repository.** The README has a quick start that was run from a clean copy: a desk draws a card and a stand-in renderer presses its button. Beside it are the documents under `docs/`, the contributing guide, the security policy, the code of conduct, and CI workflows that run the build with the publication profile, the docs lint, and an OSV dependency scan.
